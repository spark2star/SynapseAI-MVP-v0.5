## What Was Fixed

### Issue 1: Gemini Model Not Working
**Problem:** Reports falling back to template instead of using AI

**Root Cause:** Code was hardcoded to use wrong model/region
- Hardcoded: `us-central1` + `gemini-1.5-flash`
- Your config: `global` + `gemini-2.5-flash`

**Fix:** Updated `backend/app/services/gemini_service.py` to read from `.env`

**Status:** ✅ Code fixed

---

### Issue 2: Database Column Too Small
**Problem:** 500 error - "value too long for type character varying(10000)"

**Root Cause:** Encrypted transcripts exceeded 10,000 character limit
- Original transcript: ~7,000 characters
- After encryption: ~17,600 characters
- Database limit: 10,000 characters

**Fix:** 
1. Updated model to use 50,000 character limit
2. Ran database migration to update columns

**Status:** ✅ Database migrated successfully

## Troubleshooting

### If reports still use fallback template:
1. Check backend logs for Gemini initialization message
2. Verify `.env` file has correct values:
   ```env
   VERTEX_AI_LOCATION=global
   GEMINI_MODEL=gemini-2.5-flash
   GCP_PROJECT_ID=synapse-product-1
   ```
3. Ensure `gcp-credentials.json` exists and is valid

### If you still get "value too long" error:
1. Verify database migration ran successfully (it did!)
2. Check column sizes:
   ```sql
   SELECT column_name, character_maximum_length 
   FROM information_schema.columns 
   WHERE table_name = 'transcriptions' 
   AND column_name IN ('transcript_text', 'original_transcript');
   ```
   Should show 50000 for both
