# Requirements Document

## Introduction

This document specifies the requirements for implementing a mandatory doctor profile completion workflow and a secure digital signature system for clinical reports in SynapseAI. The feature ensures that all newly verified doctors complete their professional profiles before accessing the system, and provides a legally compliant mechanism for digitally signing clinical reports with password re-authentication and audit trails.

## Glossary

- **SynapseAI System**: The healthcare platform that manages doctor profiles, patient consultations, and clinical reports
- **Doctor User**: A verified medical professional with an account in the SynapseAI System
- **DoctorProfile**: The database entity storing professional information about a Doctor User
- **Clinical Report**: A medical document generated by the SynapseAI System containing patient consultation details
- **Digital Signature**: A cryptographic hash-based verification mechanism applied to Clinical Reports
- **Profile Completion Workflow**: The mandatory onboarding process requiring Doctor Users to provide professional details
- **Signature Hash**: A SHA-256 cryptographic fingerprint of Clinical Report content at signing time
- **Audit Log**: A tamper-evident record of system events for compliance and security purposes

## Requirements

### Requirement 1: Mandatory Profile Completion

**User Story:** As a newly verified doctor, I want to complete my professional profile immediately after my first login, so that all reports I generate contain accurate and complete professional information.

#### Acceptance Criteria

1. WHEN a Doctor User logs in for the first time after verification, THE SynapseAI System SHALL redirect the Doctor User to the profile completion page
2. WHILE the DoctorProfile profile_completed flag is false, THE SynapseAI System SHALL prevent the Doctor User from accessing any dashboard or clinical features
3. WHEN the Doctor User successfully submits the profile completion form, THE SynapseAI System SHALL set the profile_completed flag to true and grant access to the dashboard
4. WHERE the Doctor User has password_reset_required set to true, THE SynapseAI System SHALL enforce password change before profile completion

### Requirement 2: Professional Information Collection

**User Story:** As a doctor completing my profile, I want to provide my qualifications, clinic details, logo, and digital signature, so that my reports appear professional and credible.

#### Acceptance Criteria

1. THE SynapseAI System SHALL accept and store qualifications text up to 255 characters in the DoctorProfile entity
2. THE SynapseAI System SHALL accept file uploads for clinic logo and digital signature images
3. WHEN a Doctor User uploads logo or signature files, THE SynapseAI System SHALL store the files securely and save the URLs to the DoctorProfile entity
4. THE SynapseAI System SHALL accept and store clinic_name, clinic_address, and phone in the UserProfile entity
5. THE SynapseAI System SHALL display the Doctor User's full_name and medical_registration_number as read-only confirmation fields

### Requirement 3: Secure Report Signing

**User Story:** As a doctor, I want to digitally sign my completed clinical reports with password verification, so that the signature is legally defensible and cannot be repudiated.

#### Acceptance Criteria

1. WHEN a Doctor User attempts to sign a Clinical Report, THE SynapseAI System SHALL require password re-authentication
2. IF the provided password does not match the stored password_hash, THEN THE SynapseAI System SHALL return an unauthorized error and prevent signing
3. WHEN password authentication succeeds, THE SynapseAI System SHALL generate a SHA-256 hash of the Clinical Report content
4. WHEN a Clinical Report is signed, THE SynapseAI System SHALL store the Signature Hash, update status to 'signed', and record signed_by and signed_at timestamps
5. WHERE a Clinical Report status is not 'completed', THE SynapseAI System SHALL disable the sign action

### Requirement 4: Audit Trail and Non-Repudiation

**User Story:** As a system administrator, I want every report signing action to be logged with complete audit details, so that we maintain legal compliance and can verify signature authenticity.

#### Acceptance Criteria

1. WHEN a Doctor User successfully signs a Clinical Report, THE SynapseAI System SHALL create an Audit Log entry with event type REPORT_SIGNED
2. THE SynapseAI System SHALL record the Doctor User identifier, timestamp, and Clinical Report identifier in the Audit Log
3. THE SynapseAI System SHALL store the Signature Hash in the Clinical Report entity for future verification
4. THE SynapseAI System SHALL ensure the Audit Log entry is created atomically with the Clinical Report status update

### Requirement 5: Data Integrity and Single Source of Truth

**User Story:** As a doctor, I want my profile information to automatically populate all generated reports and prescriptions, so that my professional details are consistent across all documents.

#### Acceptance Criteria

1. THE SynapseAI System SHALL use DoctorProfile qualifications as the source for credentials on all Clinical Reports
2. THE SynapseAI System SHALL use UserProfile clinic details as the source for practice information on all Clinical Reports
3. THE SynapseAI System SHALL use the digital_signature_url from DoctorProfile when rendering signed Clinical Reports
4. THE SynapseAI System SHALL use the logo_url from UserProfile when rendering Clinical Reports

### Requirement 6: User Interface Flow Control

**User Story:** As a newly verified doctor, I want the system to guide me through password reset and profile completion in the correct order, so that I can start using the platform efficiently.

#### Acceptance Criteria

1. WHEN a Doctor User logs in, THE SynapseAI System SHALL check password_reset_required before checking profile_completed
2. IF password_reset_required is true, THEN THE SynapseAI System SHALL redirect to the password change page
3. WHEN password reset is complete, THE SynapseAI System SHALL check profile_completed status
4. IF profile_completed is false, THEN THE SynapseAI System SHALL redirect to the profile completion page
5. WHEN both password_reset_required is false and profile_completed is true, THE SynapseAI System SHALL allow access to the dashboard

### Requirement 7: Signature Modal User Experience

**User Story:** As a doctor reviewing a completed report, I want a clear and secure interface to sign the report, so that I understand the finality of my action and can authenticate safely.

#### Acceptance Criteria

1. WHEN a Clinical Report has status 'completed', THE SynapseAI System SHALL enable the sign action button
2. WHEN a Doctor User clicks the sign button, THE SynapseAI System SHALL display a signature confirmation modal
3. THE SynapseAI System SHALL display a clear message about the finality of the signing action in the modal
4. THE SynapseAI System SHALL provide a password input field in the signature modal
5. WHEN signing succeeds, THE SynapseAI System SHALL close the modal and update the UI to reflect 'signed' status
6. IF signing fails due to incorrect password, THEN THE SynapseAI System SHALL display an error message without closing the modal
